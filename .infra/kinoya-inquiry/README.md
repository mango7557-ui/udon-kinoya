# Administrator-first inquiries: isolated candidate, not active

This branch wires the new public forms and adds a new staff inbox alongside the unchanged legacy admin module. The code is not deployed. Without the new API and production App Check configuration, public forms stay inactive and show the phone fallback. Do not publish any subset before the reviewed atomic release; there is no production storage, email, permission change, service installation, or credential use here.

## Flow

1. Contact form gives explicit consent notice for storage in the admin inbox and forwarding of message/type/receipt ID via the approved email processor to the business mailbox. Do not encourage sensitive personal details in the free-text message. Phone/name/region are not dedicated fields in the notification. Free text itself may include personal data.
2. Same-origin JSON POST arrives with Firebase App Check for the exact registered public web app and a random per-attempt idempotency UUID. The browser keeps retry state only in tab memory. No public direct database permission, email recipient field, FormSubmit fallback, or analytics customer event.
3. A server SDK transaction persists the inquiry, rate counters, and a notification job. Success returns only the receipt ID and only after commit. Duplicate requests with the same ID and normalized fields return the same receipt; a different payload using that ID is rejected. Invalid, over-limit, or failed saves never generate a pending job.
4. An authenticated admin receives records only via a server endpoint that verifies token revocation and the separate `kinoyaInquiryAdmin` claim. The viewer treats fields as text nodes, clears its display when auth changes/denied, paginates and updates status with expected-value guarding. No client-side deletion, email forwarding, or migration of legacy leads. Verify authenticated staff access and logout across devices.
5. A private server worker claims each outbox entry in a transaction, then sends a plaintext email via a configured authenticated SMTP transport to one fixed approved business address. It does not include structured name/phone/region fields. A stable Message-ID is for reconciliation and is not an SMTP delivery/deduplication guarantee. `accepted` indicates transport acceptance; a timeout, reject, crash, or unresolved `sending` is quarantined for reconciliation, not blindly requeued. Receipt confirmation is independent of email visibility. Never log request bodies, tokens, SMTP envelopes, or message text.

## Verify and finish deployment

- Use an approved environment and scoped service account. Deploy Functions/Hosting only after owner approval for any new service, costs, credentials or privileges. Firebase Hosting rewrites should target the two exact API paths in the existing site target and precede any broad rewrite. Provide a TLS-only verified SMTP sender/host/port, password or app secret via the server secret manager, and approved **server-only** recipient. Never commit recipient configuration, mail credentials or HMAC keys. Configure real transport saturation/connection timeouts. A worker invocation and schedule must be private and explicitly authorized; it should enumerate pending job IDs only and buffer/reconcile stuck records without lead details in logs. No new middleware/provider was installed here.
- Obtain approved permissions and billing for Firebase Functions/Cloud Run and the planned managed services. Use Firebase SDKs pinned by the implementer. Bind `createFirebaseInquiryAdapters` to initialized Firestore/Auth/App Check SDKs inside the runtime, use exact canonical Hosting origin and exact App Check app IDs in allowlists, configure application-level and edge request ceilings, and configure Secret Manager and workload identity. App Check alone is not a complete anti-abuse control; verify traffic limits and monitoring, and do not rely on spoofable public forwarded IP headers.

Exercise unauthenticated and ordinary authenticated reads/writes with the exact intended rules in the emulator; confirm denied. An explicit deny cannot override a matching allow. Do not redeploy shared legacy rules; if necessary use a separately approved locked Firestore database with server-only access. Set an approved lead/outbox retention and deletion policy; enable expiry on rate counters and test background expiration in target configuration.

The form markup carries a stable canonical source route so homepage embedding does not emit an invalid root route. Then, separately authorize a clearly marked no-personal-data delivery test with the approved real provider and mailbox.
