# KINOYA Atelier 개편 점검

## 범위

- 기존 본문 문구·사진·메뉴 가격·CMS 키·통합 상담 폼 유지.
- 전체 공통 스타일: `css/atelier.css`. 메인·국문·영문·일문 및 매장 상세 페이지에 `kinoya.css`를 통해 적용.
- 관리자 공통 스타일: `admin/studio.css`. 전체 관리자·메인 편집기·사람들 편집기 적용.
- 섹션 목차·맨 위로·소셜 목적지 연결: `js/atelier.js`.
- 관리자 전체 카테고리 검색, 숨겨진 섹션 딥링크, 키보드 탭 이동, 미저장 필드 수 표시.
- 공식 가이드 디자인과 메인 푸터의 가이드 접근 경로 추가.
- 메인 Organization의 본사 번호·이메일·법인명을 현재 국문 푸터와 일치시킴. 근거 없는 리뷰·평점·성과 스키마는 추가하지 않음.

## 검색 및 AI 답변 대응

`npm test`는 51개 사이트맵 페이지의 정적 제목·설명·본문·대표 제목·JSON-LD와 상담 폼/CMS 연결 계약을 확인한다. 공식 가이드의 질문답변과 원문 링크, `llms.txt`, sitemap, hreflang은 유지한다. 순위나 AI 인용 보장과는 별개다.

## 운영자가 확인해야 할 기존 상태

1. **도메인:** canonical·sitemap·hreflang은 `https://www.udonkinoya.com/` 기준이고 현재 공유 주소는 GitHub Pages다. 정식 도메인이 이 배포를 가리키는지 확인 후 하나의 기준으로 운영해야 한다.
2. **연락처:** 현재 국문 푸터 본사 번호는 `1551-8748`, 통합 문의 대표번호는 `0507-1408-1984`, 공식 가이드·번역본에는 `1668-2750`이 남아 있다. 본문 유지 요청에 따라 번호를 일괄 치환하지 않았다. 각 번호의 용도 확인이 필요하다.
3. **관리자 인증:** 실제 계정 인증이 없고 현재 `firestore.rules`의 `site_config`는 익명 읽기·쓰기를 허용한다. 디자인 변경은 접근 제어가 아니다. Firebase Authentication과 관리자 권한을 검증하는 서버/Firestore 규칙 배포가 별도로 필요하다. UI만 잠그는 가입/로그인 화면은 만들지 않았다.
4. **API 키:** 기존 `enc:v1`은 공개 코드의 고정 문자열로 XOR 복원하는 난독화이며 비공개 암호화가 아니다. 이전 답변의 완전 비공개라는 설명은 정확하지 않다. YouTube 키를 서버 비밀 저장소로 옮기고 프록시 인증·기존 키 폐기/재발급이 필요하다. Firebase 웹 설정 키와 YouTube 비밀 키는 구분해야 한다.
5. **이메일:** FormSubmit 연동은 수신처 활성화와 실제 수신 확인이 필요하다. 테스트는 모의 응답이며 메일함 도착을 증명하지 않는다.
6. **정적 SEO와 CMS:** 관리자 저장은 브라우저 콘텐츠를 갱신하지만 GitHub Pages의 원본 HTML 메타/JSON-LD까지 자동 빌드하지 않는다. 카카오 공유·크롤러용 업데이트에는 정적 재배포 또는 서버 렌더링이 필요하다.

## 적용 상태

이번 작업은 로컬 파일 수정이다. 원격 커밋·푸시, DNS, 인증 서비스 활성화, Firestore 규칙 변경은 수행하지 않았다.

## 검증 결과

- `npm test`: 서버 통합·검색 구조·폼 계약 3개 테스트 통과.
- 브라우저 PC 1440px / 모바일 390px: 17개 검사 통과. 목차, 모바일 메뉴, 단일 문의 제출, 관리자 메뉴 검색·백업·상담 바로가기, 가로 넘침, 51개 페이지 HTTP/메타/H1/JSON-LD 검사 포함.
- `/tests/admin-reliability.html`: 29개 검사 통과. 실제 운영 데이터는 쓰지 않고 픽스처로 검증.
- JavaScript 문법과 `git diff --check` 통과.
- 모의 DB·메일 응답으로 검증했으므로 실서비스 권한이나 이메일 도착까지 검증한 것은 아니다.
